# FPGA：RGB565 → BGR888 实现说明

面向 RK3568 + PCIe FPGA 车牌识别工程（`5.19_v1_plate_computer`）。  
目标：在 FPGA 侧完成颜色转换，减轻 CPU `rgb565_to_rgb888_local` 开销（当前约 5–6 ms/帧）。

---

## 1. 背景与目标

### 现状

```text
摄像头/HDMI → FPGA 帧缓冲(RGB565)
    → PCIe DMA → RK3568 DDR
    → CPU: RGB565 → RGB888 → BGR   （上位机）
    → 检测 / 识别 / 显示
```

### 目标

```text
摄像头/HDMI → FPGA: RGB565 → BGR888 缓冲
    → PCIe DMA → RK3568 DDR
    → 上位机直接使用 BGR（可不再转色）
    → 检测 / 识别 / 显示
```

### 收益

| 项目 | 说明 |
|------|------|
| CPU | 省掉约 5–6 ms 的 `rgb565_to_rgb888_local` |
| 上位机 | 改动小；驱动协议已预留 |
| 显示/推理 | 拿到缓冲即可当 OpenCV `CV_8UC3` BGR 使用 |

---

## 2. 与现有软件的约定（勿改寄存器地址）

驱动头文件：`driver/pango_pci_driver.h`

| 宏 / 寄存器 | 值 | 含义 |
|-------------|-----|------|
| `DMA_SRC_SEL_OFFSET` | **0x1C0** | 写：选择 DMA 数据源 |
| `DMA_SRC_SEL = 0` | 默认 | **RGB565** 预览/兼容路径 |
| `DMA_SRC_SEL = 1` | 新增 | **BGR888** 推理路径 |
| 分辨率 | 1280 × 720 | 固定 |
| RGB565 行有效字节 | 2560 | `1280 × 2` |
| RGB565 行 stride | 4096 | 行尾 padding |
| BGR888 行有效字节 | **3840** | `1280 × 3` |
| BGR888 行 stride | **4096** | 与现驱动一致，后 256 字节填 0 |

上位机开关（FPGA 就绪后）：

```bash
PCIE_FPGA_RGB888=1 ./run.sh
```

对应 ioctl：`PCI_MAP_INFER_FRAME_CMD` / `PCI_READ_INFER_FRAME_CMD`。  
**驱动侧协议已预留，一般无需为转色新造 ioctl；工作量主要在 FPGA。**

> 说明：软件宏名仍可能写作 `RGB888`，联调约定 **`SEL=1` 时实际输出 BGR888**，便于 OpenCV 直接使用。

---

## 3. 是否还要做 DMA？

**要。** 转色在 FPGA 内完成；DMA 仍负责把帧搬到 CPU。

| 部分 | 是否改动 | 说明 |
|------|----------|------|
| 565→BGR 计算 | FPGA 新增 | 与 DMA 引擎无关 |
| DMA 引擎 | 尽量复用 | 仍用现有 Host 读 DMA |
| DMA 读谁 | 要改 | `0x1C0=1` 时读 BGR 缓冲 |
| DMA 搬多少 | 要改 | 每行有效字节 2560 → 3840 |

没有 DMA，BGR 数据到不了上位机；有了 FPGA 转色，DMA 只是换「搬哪块内存、每行多长」。

## 4. 像素转换公式

与当前上位机 `rgb565_to_rgb888_local` 对齐（先扩位，再按 BGR 落盘）：

```text
输入：16-bit RGB565 像素 pix

R5 = (pix >> 11) & 0x1F
G6 = (pix >>  5) & 0x3F
B5 =  pix        & 0x1F

R8 = R5 << 3          // 可选更平滑：R5<<3 | R5>>2
G8 = G6 << 2          // 可选：G6<<2 | G6>>4
B8 = B5 << 3          // 可选：B5<<3 | B5>>2

输出字节序（BGR888）：
  addr+0 = B8
  addr+1 = G8
  addr+2 = R8
```

**不要**先写成 RGB888 再二次转换；扩位时直接按 BGR 写入帧缓冲。

---

## 5. 推荐实现步骤

### 阶段 A：源选择寄存器

1. 实现 BAR 寄存器 **`0x1C0`**
   - 写 `0` → DMA 读口接 **RGB565** 帧缓冲
   - 写 `1` → DMA 读口接 **BGR888** 帧缓冲
2. 复位默认 **`0`**（保证现有上位机不改也能跑）
3. 建议在 **帧边界** 切换，避免半帧花屏/撕裂

### 阶段 B：RGB565 → 24bit 扩位

- 对每个像素按第 4 节公式扩位
- 可与写 DDR/BRAM 流水线合并，避免额外整帧拷贝（若资源允许）

### 阶段 C：按 BGR 打包落盘

- 每像素 3 字节：`B, G, R`
- 每行有效 3840 字节，pad 到 stride **4096**

### 阶段 D：DMA 对齐与状态

- 行触发或整帧连续地址均可，但 stride 必须与驱动一致（4096）
- 注意 4KB 边界；驱动侧有 `DMA_STATUS_4KB_ERR`
- `dma_done` / `busy` 行为与现有 RGB565 路径保持一致

---

## 6. 帧缓冲布局

### RGB565（`SEL=0`，保持兼容）

```text
行 y 起始 = y * 4096
有效数据 = 2560 字节（1280 像素 × 2）
[2560 .. 4095] = padding
```

### BGR888（`SEL=1`，新增）

```text
行 y 起始 = y * 4096
有效数据 = 3840 字节（1280 像素 × 3）
[3840 .. 4095] = padding（建议填 0）
整帧映射约 = 720 * 4096 字节
```

---

## 7. 验收清单（FPGA 交付）

- [ ] `0x1C0=0`：输出与现网 RGB565 **逐字节一致**（回归）
- [ ] `0x1C0=1`：输出 BGR888，1280×720，stride=4096
- [ ] 切换源后最多 1 帧内生效（优先帧结束后再切）
- [ ] DMA done/busy 与 565 路径一致
- [ ] 720p @ 15–30 fps 带宽足够（888 约为 565 的 1.5 倍）
- [ ] 提供 golden：同一场景的 `frame_565.bin` + `frame_bgr.bin`

---

## 8. 联调顺序

1. **只开 FPGA BGR，先不跑推理**  
   `PCIE_FPGA_RGB888=1`，抓一帧用 OpenCV/Python 看颜色（蓝天、蓝牌最容易看出 R/B 反了）。
2. **颜色正确后**再接检测/识别。
3. 看 `[latency]`：`rgb_convert` 应从约 5–6 ms 降到约 0–2 ms（已是 BGR 时可接近 0）。

若颜色反了：优先在 FPGA 改接线为 BGR，而不是长期在上位机补 `cvtColor`。

---

## 9. 风险与注意

| 风险 | 建议 |
|------|------|
| 切源瞬间撕裂 | 在消隐/帧结束后切换 `DMA_SRC_SEL` |
| R/B 通道反了 | 先目视出图，再锁进协议文档 |
| stride ≠ 4096 | 必须同步改驱动宏；**优先保持 4096** |
| 一期做太多图像处理 | gamma/对比度等放二期；一期只做 565→BGR888 |
| 未实现就开软件开关 | 上位机会失败并回退 CPU 路径，不会自动变快 |

---

## 10. 给 FPGA 的一句话需求

> 在现有 RGB565 DMA 旁路增加 BGR888 输出；通过 BAR 寄存器 `0x1C0` 选择数据源（0=RGB565，1=BGR888）；分辨率 1280×720，行 stride=4096；默认 0 保持兼容；切换在帧边界生效。

## 11. 软件侧对照（联调时）

| 角色 | 动作 |

## 12. 工作量粗估

| 项 | 难度 | 说明 |
|----|------|------|
| `0x1C0` 源选择 | 低 | 多路选择 |
| 565→888 扩位 | 中 | 核心逻辑 |
| 按 BGR 打包 | 极低 | 换线/换字节序 |
| DMA 行长/stride | 中 | 对齐与联调 |
| 整包联调 | 中 | 颜色、撕裂、带宽 |

有现成 RGB565 帧缓冲时，通常为 **几天级** 工作量；难点在时序/DMA 对齐，不在 BGR 通道顺序本身。
